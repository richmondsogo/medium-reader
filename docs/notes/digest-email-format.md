# Medium Daily Digest Email Format Discovery

This document details the reverse-engineered structure of Medium Daily Digest emails based on empirical analysis of fixtures in `fixtures/emails/`.

## 2. MIME Structure and Encodings

Every fixture exhibits an identical MIME structure:

```
multipart/alternative; boundary=<HEX_BOUNDARY_STRING>
├── text/plain; charset=utf-8; Content-Transfer-Encoding: quoted-printable
└── text/html; charset=utf-8; Content-Transfer-Encoding: quoted-printable
```

- **Multipart Type**: `multipart/alternative` with no nested `multipart/related` or `multipart/mixed`.
- **Encodings**: Both the plain text and HTML parts use `utf-8` character sets and `quoted-printable` transfer encoding.
- **Attachments**: None (`attachmentsCount: 0`). Images are hosted externally on Medium CDNs (`miro.medium.com`), not attached as MIME inline parts (`CID`).
- **Synchronicity**: Both text and HTML parts represent the exact same story inventory. The plain text version renders links inline as `Title Text (https://medium.com/...)`.

## 4. Article Link Behavior & Redirects

- **Direct vs Redirect**: All article links in the emails are **direct `medium.com` URLs**. They are **NOT** tracking redirects through SendGrid (`ct.sendgrid.net`) or a Medium redirect proxy.
- **Host**: Always `medium.com`.
- **Destination Discovery**:
  - The destination story is contained directly in the URL pathname:
    `/@<author-handle>/<title-slug>-<post-id>`
    *(e.g., `/@qtalen/from-openspec-to-aidlc-how-i-improved-my-teams-ai-code-quality-023c7749c518`)*
  - The destination is **not** hidden in query parameters.
  - **No HTTP redirect or network request is necessary** to identify the article URL or post ID.
- **Query Parameter Handling**:
  - The URL includes a `?source=email-<USER_ID>-<TIMESTAMP>-digest.reader-...` query parameter.
  - Stripping this query string gives the clean canonical URL of the article.

## 5. Per-Article Metadata & HTML Structure

### Metadata Availability in Email

| Field | Present in Email? | Location & Selectors |
| :--- | :---: | :--- |
| **Title** | Yes | Located in `<h2 class="...">` inside `<a href="...article-url...">`. Also present in thumbnail `img[alt]`. |
| **Author** | Yes | Text of `<a href=".../@author...">` located inside the author header row preceding the `<h2>`. |
| **Publication** | Conditional | Text of `<a href=".../pub-name...">` preceded by a separator `<span ...>in</span>`. Present only when published in a publication. |
| **Snippet** | Yes | Located in `<h3 class="...">` immediately below `<h2>` within the same `<a>` tag. |
| **Reading Time** | Yes | Text matching `/\d+\s*min read/i` inside a `<span>` in the card footer row. |
| **Date** | **No** | **Absent from article cards and email body.** Individual story publication dates are not included in Medium digests. The only date is the email delivery `Date:` header. |
| **Member-Only** | Yes | Indicated by `<img alt="Member-only content" src="..." width="15" height="15">` located immediately before the reading time span. Absent for free stories. |
| **Claps Count** | Yes | Text of `<span>` following `<img alt="Claps" src="...">` (e.g. `56`, `1.4K`, `9.8K`). |
| **Responses Count**| Yes | Text of `<span>` following `<img alt="Responses" src="...">` (e.g. `166`, `92`, `151`). |
| **Thumbnail URL** | Yes (~93%) | `<img width="160" height="107" src="...">` wrapped in an `<a>` tag adjacent to the title block. |
| **Author Avatar** | Yes | `<img width="20" height="20" src="...">` wrapped in the author profile `<a>` tag. |

### Reliable Card Selectors & Extraction Strategy

- **Brittleness of CSS Classes**: The emails use atomic, minified CSS classes (`div.cb.cc.cd.ce`, `h2.dj.dk.dl...`). While consistent across current fixtures, these class names are compilation artifacts and subject to change without warning.
- **Robust Semantic Anchors**:
  1. Locate articles by scanning for `h2` elements wrapped by an `a` tag whose `href` contains a Medium story post ID:
     `a:has(h2)` where `href` matches `/[^/]+-[a-f0-9]{8,16}(\?|$)/` and host is `medium.com`.
  2. Filter out non-article entries (such as the footer careers link and policy links, or recommendation cards).
  3. Traverse up from `h2` to the enclosing card container (the common ancestor element containing the author row, title row, and footer row).
  4. From that container:
     - **Author**: Find `a[href*="/@"]` preceding `h2` that does not contain a post ID.
     - **Publication**: Find `a` following the author link that is preceded by text `in`.
     - **Title**: `h2.text()`.
     - **Snippet**: `h3.text()`.
     - **Reading Time**: Regex search for `/\d+\s*min read/i`.
     - **Member-Only**: Check for `img[alt="Member-only content"]`.
     - **Claps / Responses**: Find `img[alt="Claps"]` and `img[alt="Responses"]` and grab their sibling text.

## 7. Parsing Fragility & Hazards

1. **Obfuscated Atomic CSS Classes**:
   - Class names like `.cb.cc.cd.ce` or `.dj.dk.dl` are randomly generated or minified by CSS-in-JS build systems. Never rely on class names as primary selectors.
2. **Footer Links Masquerading as Articles**:
   - Careers (`/jobs-at-medium/work-at-medium-959d1a85284e`), Privacy Policy (`/medium-privacy-policy-f03bf92035c9`), and Terms of Service (`/medium-terms-of-service-9db0094a1e0f`) are published on Medium as standard articles with 12-character hexadecimal post IDs. A regex matching `-[a-f0-9]{8,16}` across the entire document will extract these footer links as articles unless card scoping or path exclusions are applied.
3. **Non-Article `<h2>` Tags**:
   - The footer callouts ("See more of what you like...", "Read from anywhere.") also use `<h2>` elements. Any article scraper querying `$('h2')` will pick up footer marketing copy unless verified against an article URL in the enclosing `<a>`.
4. **Missing Thumbnails**:
   - Approximately 7% of articles (e.g. Card 13 in Sep 08, Card 7 in Sep 24) have no thumbnail image. The parser must not assume an image link exists alongside the title link.
5. **Optional Publications**:
   - Not all authors publish within a publication. The publication link and separator `in` are optional and must be parsed leniently.
6. **No Article Publication Dates**:
   - The email does not contain story publication dates. Ingestion must associate articles with the email's dispatch timestamp (`Date:` header) or retrieve published timestamps when fetching article HTML in subsequent steps.
7. **Ellipsis in Snippets**:
   - Medium truncates snippets with character `…` (U+2026). Snippets should be treated as teaser previews rather than complete opening paragraphs.
